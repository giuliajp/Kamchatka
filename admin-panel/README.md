# Административная панель «Авачи»

Отдельное приложение React + TypeScript + Vite. Версии согласованы с мини-приложением;
используются нативные формы, таблицы, VK Icons и Leaflet, без универсального CRUD-конструктора.

Описание API: [docs/api.md](../docs/api.md).

## Запуск

Node.js 22.21+ и npm 10+, из `admin-panel`:

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Админка: http://127.0.0.1:5174. `VITE_DEV_API_TARGET` по умолчанию
`http://127.0.0.1:8000`, `VITE_API_BASE_URL` — `/api`.
Создание администратора и серверные настройки — в [backend/README.md](../backend/README.md).
Пароли и интеграционные ключи в frontend-настройки не помещаются.

## Рабочие сценарии

| Раздел | Возможности |
|---|---|
| Гонка | Сезоны, дисциплины, этапы и статусы, КП, обязательный отдых, маршруты GPX/KML/KMZ |
| Участники | Поиск спортсмена прошлых сезонов, заявки, регион, собаки, статусы, биография и `photo_url` |
| Мониторинг | Поиск по имени/номеру/IMEI, фильтры состояния и КП, реальная телеметрия, быстрый ввод/исправление отметки, журнал, трекеры и назначения |
| SOS | Отдельный сигнал в шапке и мониторинге, карточка, модальное закрытие с обязательной причиной, история |
| Результаты | CSV-проверка/импорт, просмотр/исправление, штрафы, публикация, утверждение, специальная процедура исправления окончательного протокола с основанием и утвердившим |
| Push | Сообщение и поддерживаемый сегмент, подтверждение отправки, серверный журнал и ошибки доставки |
| Болельщики | Серверный рейтинг/счётчики, динамика через CSV |
| Контент | Создание, изменение, удаление, порядок и публикация программы, локаций, FAQ, контактов и «Гостям»; просмотр медиа |

Вход: `/admin/login`, проверка `/admin/me`, Bearer-токен только в `sessionStorage`.
При `401` требуется повторный вход; заполненные формы остаются в памяти для того же
организатора. Другой пользователь и явный выход сбрасывают рабочее состояние.

Импорт: сохраните Excel в **CSV**, выберите файл, выполните **«Проверить»**, изучите
ошибки строк/предупреждения, отдельно нажмите **«Загрузить»**. Замена файла или неудачная
повторная проверка сбрасывают разрешение загрузки. XLS/XLSX не разбираются в браузере.
См. [серверный формат CSV](../docs/csv-import.md).

Даты вводятся по Камчатке и отправляются с `+12:00`. При ошибках значения сохраняются.
Push, публикация и другие записи автоматически не повторяются. GPS не заполняет
официальные времена. История батареи, вложения, черновики и отдельный источник
подтверждения отметки ожидают серверных API. Фото спортсмена задаётся URL.

## Дизайн и Storybook

[Мониторинг](https://www.figma.com/design/GxGegMJVi9NCC8FMG7Tgeb/?node-id=525-14756),
[Admin UI kit](https://www.figma.com/design/GxGegMJVi9NCC8FMG7Tgeb/?node-id=525-18242).
Светлая тема — начальная; тёмная выбирается явно. Форма справа, таблица, подсветка
просрочки/SOS, вкладки, шапка и логотип пересверены по макету и пользовательским
скриншотам. Логотип — тот же Figma SVG, что уже используется в мини-приложении;
геометрия не перерисовывалась. Детальный Figma MCP недоступен из-за лимита аккаунта;
попиксельное совпадение не заявляется.

```bash
npm run check
npm audit --audit-level=moderate
npm run storybook
```

Storybook: http://127.0.0.1:6007, отдельные истории входа, навигации, форм, таблиц,
статусов, обычного/просроченного/SOS/пустого мониторинга и остальных разделов.
Есть переключатели ширины 768/1280/1920, текста 100/200% и темы. Истории изолированы
в iframe, чтобы их HTTP-фикстуры не подменяли друг друга в Docs.

`check`: lint, TypeScript, тесты, production и Storybook. Пороги всех рабочих TS/TSX-файлов:
100% statements/branches/functions/lines. Браузерные проверки production
обоих приложений запускаются командой `npm run test:e2e` из `frontend`.
PATCH отметки требует `expected_updated_at`: backend и админка обновляются совместно.
