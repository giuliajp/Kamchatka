# Подготовка к визуальной приёмке

Обновлено 4 ноября 2026. Ветка `codex/backend-design-update`. Эталон — [Figma, «Для разработки» 339:7522](https://www.figma.com/design/u3ZUZKR1AWhc7cNFAzwd9o/?node-id=339-7522).

**Исправления внесены, но полная визуальная приёмка ещё не закрыта.** Поведенческие ошибки устранены, ключевая геометрия измерена повторно. Утверждать точное совпадение всех 57 состояний и 80 семейств UI-kit нельзя: Figma MCP возвращает лимит, браузерные JPEG не дают точных токенов и часть исходных изображений отсутствует. Это ограничение не заменено отметкой «готово».

Изменения этого прохода клиентские. Production, Figma, серверные контракты и подписанные параметры VK не изменялись этим UI-проходом. В той же ветке отдельно выполняется кодовый аудит; его изменения и проверки описаны в [review-fixes.md](review-fixes.md).

## Покрытие и предел результата

- Все **57 актуальных состояний** открыты в браузере; **2 скрытых старых** сохранены архивными. Для каждого — узел, размер, реализация, снимок и отдельный статус точного соответствия: [реестр](../output/ui-review/screen-coverage.md).
- Все **80 семейств двух UI-kit** перечислены. Полная сверка их стилей/вложенных вариантов остаётся **не проверено**. Отрисовка доступных историй подтверждает работоспособность стенда, но не соответствие Figma: [реестр](../output/ui-review/component-coverage.md).
- **25 поведенческих стрелок** и дополнительный сценарий раскрывающейся «Гонка» имеют рабочие соответствия. Шесть линий пояснений маркеров не считаются переходами: [Figma → фактически](../output/ui-review/transition-coverage.md).
- Итоговая матрица: 7 размеров × 2 темы × 2 масштаба текста × 8 экранов = **224 состояния**. Размеры: 320×568, 360×800, 390×844, 430×932, 768×1024, 1280×900, 844×390. Проверены карта, участники, результаты, программа, профиль, событие, полная локация и админка с визуальной формой. Горизонтального переполнения документа нет. Таблицы/дни/фотополосы имеют предусмотренную внутреннюю прокрутку.
- На коротких экранах и при 200% карта и меню идут в потоке и могут требовать вертикальной прокрутки; управление не закрывается нижней панелью. Это адаптация, для которой в Figma нет отдельного landscape-эталона.
- Проверены ошибки/загрузка API, offline, старые координаты, ошибки тайлов, длинные имена, большие счётчики и отсутствие фото. Числовые результаты и сценарии — [verification.json](../output/ui-review/verification.json). Полные локальные снимки/DOM — `output/ui-review/fixes/`.

## Фикстуры и рабочий режим

`MonitoringPresentationContext` по умолчанию пуст. Только Storybook предоставляет обработчики классификации SOS, вложения/черновика, истории и батареи. В рабочем режиме ложный сигнал отключён, вложения/черновики недоступны; обычное подтверждение SOS использует существующий endpoint. Ни одна демонстрационная запись не отправляется в рабочий API.

`StageMediaViewModel` передаётся в общий компонент только для визуальных историй завершённого этапа. Галерея использует fragment URL; следующая фотография не создаёт новую запись Back. Исходное видео отсутствует, поэтому успешное воспроизведение не имитируется. Декоративная оболочка VK подключена только к полным историям Storybook; реальное приложение её не дублирует.

Одинаковые с Figma имена, все изображения, даты и количество строк пока не воспроизведены для каждого экрана. Это отдельное незакрытое условие точной приёмки, а не оправдание расхождений. Противоречие №14/№15 устранено внутри сценария SOS: везде используется запись №14.

## Проверки

Результаты `npm run check` обоих приложений фиксируются в [checks.json](../output/ui-review/checks.json). Пороги 100% на файл не снижены. Добавлены проверки раскрытия меню/черновика, URL/Back/Forward, источника/вложения/истории, решения SOS, отложенных уведомлений, галереи и прямых ссылок. Успешные тесты не являются доказательством визуальной точности.

Для повторения: [сценарии браузера](../scripts/ui-review/README.md). Полные промежуточные PNG/DOM/логи исключены из Git и сохранены локально; в репозиторий входят реестры, компактная сводка и отобранные сравнения.

## Что необходимо для закрытия приёмки

Нужен доступ к точным стилям/вариантам обоих UI-kit и исходным ассетам актуальной Figma — через восстановленный MCP/Dev Mode либо экспорт этих данных. Затем требуется сопоставить все 57 кадров на одинаковых фикстурах и закрыть оставшиеся частичные замечания. Контраст исходных цветов и согласованные серверные функции остаются исключениями. Приёмка в настоящем VK-контейнере проводится отдельно.
