## Навигация

Маршруты живут в fragment URL. `race`, `stage`, `discipline`, `mine`, `day`,
`category`, `section`, `page`, `view`, `event`, `location`, `album`, `archiveRace`,
`person`, `participant` восстанавливают соответствующий выбор.
`allStages=1` отличает общий зачёт от отдельного этапа, сохраняя выбранный этап карты.
Старые `#map`, `#results`, `#participant=…`, `entry` и query-ссылки поддерживаются.
Подписанная query-строка VK передаётся без пересборки и не включается в share-ссылку.

Открытие карточки записывает источник в историю; раскрытие той же шторки заменяет
её состояние. Назад, крестик, Escape и жест за верхнюю ручку возвращают к источнику.
Переход в другой раздел закрывает карточки. Выбранный день сохраняется.

## Обновление базы

Используются готовые API миграций `0008–0009`; контракты и серверная бизнес-логика
не менялись. Проверка настоящего PostgreSQL выявила два дефекта миграций:

- В `0008` новые `image_urls NOT NULL` теперь заполняются `[]` у существующих
  записей; временное SQL-значение по умолчанию удаляется после заполнения.
- Миграция `0010` обновляет SQL CHECK для пяти типов события и пяти типов локации.
  До неё SQL-ограничения не пропускали новые типы, хотя API уже принимал их.

Перед запуском новых клиентов применить обычную цепочку:

```bash
python -m alembic -c backend/alembic.ini upgrade head
```

Откат `0010` не удаляет записи и отклоняется, если ещё используются новые типы.
Для отката сначала изменить их в админке. Проверен upgrade заполненной `0007`,
сохранение контента, запись новых типов, безопасный downgrade и `alembic check`.

## Запуск и проверка

Подробные настройки: [backend](../backend/README.md),
[мини-приложение](../frontend/README.md), [админка](../admin-panel/README.md).
Для обеих Vite-сред `VITE_DEV_API_TARGET` должен указывать на один backend.
Для локальных личных сценариев допустим `VK_DEV_USER_ID` только при
`ENVIRONMENT=development`; реальный VK проверяет подписанные launch-параметры.

```bash
# Из корня, после установки Python-зависимостей и настройки тестовой PostgreSQL:
LC_ALL=en_US.UTF-8 .venv/bin/python -m pytest -c backend/pytest.ini backend/tests -q
# Отдельно из frontend и admin-panel:
npm ci
npm run check
```

Серверные проверки выполнены в отдельном PostgreSQL 16, без данных рабочей БД.
62 дополнительных HTTP-проверки настоящего API охватили контентный CRUD,
публикацию/скрытие, новые типы, напоминания, `/me`, настройки уведомлений, закладки
PDF и удаление локации с сохранением событий. Снимки ответов используются только
в тестовых фикстурах; production-приложение их не импортирует.

Проверки backend: **289 passed**. Порог покрытия собственных TS/TSX-файлов обоих
приложений остаётся **100% для каждого файла**; исключения и пороги не снижены.
Финальные `npm run check` обоих приложений прошли: **296 тестов frontend** и
**105 тестов админки**, lint, TypeScript, production и Storybook. Собственный код:
58 непустых файлов frontend и 12 админки — по 100% для всех четырёх метрик.
Сборщики предупреждают о крупных JS-чанках; ошибок сборки нет.

В браузере проверены мобильные размеры 360/390 px, планшет 768 px и desktop
1280/1920 px, обе темы, текст 200%, клавиатурный фокус шторки, Escape и перетаскивание
ручки. Таблицы прокручиваются внутри; внешнего горизонтального переполнения нет.
Проверен повторный вход того же организатора с восстановлением введённого текста.

Реальная доставка push через VK/фоновые задачи и публикация поста в VK в этой
локальной проверке не выполнялись. Диалоги разрешения и Share проверены Bridge-
сценариями тестов; финальную внешнюю доставку проверять в зарегистрированном VK App.
