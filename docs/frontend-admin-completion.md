## Карта готовности

| Область | Реализовано и проверено |
|---|---|
| API | Чтение/запись, проверка ответов, `error.code/details`, отмена старых запросов, raw `X-VK-Launch-Params` |
| VK | Официальный Bridge, init/оформление, visit, подтверждённое разрешение/отзыв уведомлений, отказ без записи согласия, шеринг |
| Личные данные | Серверные поддержка, «Мои», сортировка supporters, счётчики/прирост/рейтинг, уведомления участника, закладки; только память текущего пользователя |
| Карта и участник | GPS отдельно от результатов; реальные судейские прибытия/отправления и финиш; медиа и SOS на публичной карте отсутствуют |
| Навигация | Общая оболочка, пять вкладок, первый запуск, сезоны, fragment push/share и старые ссылки; архивный participant-only переход |
| Контент | Программа по дням/типам, локации сезона, маршрут/высоты, FAQ/контакты, профиль, сохранённое, новости с оригиналом VK/репостом, фото по дням |
| Недоступные медиа | `503` скрывает секцию; `stale: true` сохраняет контент с отметкой о свежести |
| Админская сессия | Login/me, Bearer в sessionStorage, повторный вход после 401; формы остаются для того же организатора, другой пользователь/выход сбрасывают их |
| Настройка гонки | Сезоны, дисциплины, этапы/статусы, КП/отдых, GPX/KML/KMZ |
| Заявки | Поиск старого спортсмена, создание/изменение заявки, регион, собаки, статус, фото по URL |
| Мониторинг | Серверная просрочка, последнее положение/батарея, поиск по имени/номеру/IMEI, фильтры, отметки, журнал, выдача/возврат трекеров и ручной опрос |
| SOS | Только админка: активный сигнал в шапке, карточка и модальное закрытие с причиной, журнал; отмена/ошибка не теряют введённый текст |
| Протокол | CSV dry-run → отчёт строк → отдельная загрузка; черновик/публикация/окончательный статус, штрафы, утверждение, особая правка окончательного результата и журнал |
| Push | Поддерживаемые сегменты, явное подтверждение, отсутствие автоповтора, реальные счётчики/ошибки серверной попытки доставки |
| Болельщики | Серверный рейтинг и счётчики, CSV динамики |
| Контент админки | Просмотр опубликованного контента с явным указанием отсутствующего редактирования |
| Storybook и CI | Пользовательский каталог расширен; отдельный каталог админки, изолированные HTTP-истории; CI matrix проверяет оба приложения |

Календарное время — `Asia/Kamchatka`; административный ввод передаёт `+12:00`.
Длительности протоколов не ограничены 24 часами. Регион и собаки на старте/финише
сохранены в официальных таблицах. Пропуски API не заменяются вымышленными значениями.

Пороги покрытия не снижались. В тестах проверены launch params, отказ VK-диалога,
смена пользователя во время разрешения, личный кэш, offline, неверные ответы,
503/stale, быстрые смены сезона, push-переходы, повторные нажатия, CSV-ошибки строк,
замена файла/запоздавший dry-run, `409`, постфинальные исправления, 401 и сбои push.

Через браузер дополнительно воспроизведены и исправлены: конфликт inline-историй
Storybook, переполнение шапки при тексте 200%, начальный фокус SOS-диалога и
наследование им красного цвета. Нативный dialog закрывается Escape; фокус при
открытии ставится в причину. На ширинах проверки внешнего горизонтального
переполнения не обнаружено; широкие таблицы имеют собственную прокрутку и видимый фокус.
Контрольные ширины подтверждены размером iframe Storybook, а не только настройкой инструмента.

Vite предупреждает о крупных JS-chunks (в том числе в Storybook); сборки успешны.
`crapper`, `dryer`, `mutator` недоступны: вместо них использованы штатные тесты,
покрытие, lint, TypeScript, аудит зависимостей и браузерная проверка.

## Реальный backend локально

Использован отдельный контейнер `avacha-complete-ui-tests` PostgreSQL 17 на порту
55441, база `avacha_ui_tests`, backend на `127.0.0.1:8012`. Существующие миграции
0001–0007 применены без изменений. Фоновый опрос трекеров выключен.
Данные полностью искусственные: два сезона, три спортсмена, один этап/маршрут/КП,
один трекер и протокол с длительностью `27:02:02`.

[Сценарий](../scripts/verify-ui-api.py) использует фиксированный localhost:8012,
администратора `ui-test` и пароль из `AVACHA_TEST_PASSWORD`; перед созданием сезонов
проверяет, что список гонок пуст. Он не сбрасывает существующую БД. Подготовка
серверного окружения/администратора — [backend README](../backend/README.md).
Для повторения нужна новая пустая тестовая БД и синтетические настройки
`VK_APP_ID=12345`, `VK_APP_SECRET=local-vk-signing-fixture`; это не рабочие ключи VK.

```bash
AVACHA_TEST_PASSWORD='<пароль тестового администратора>' .venv/bin/python scripts/verify-ui-api.py
```

`backend/.env`, виртуальное окружение и артефакты покрытия игнорируются Git.
Сохранённые JSON-ответы используются в контрактных тестах и Storybook и не содержат
паролей/токенов. Сценарий проверяет HTTP-операции, а не реальную сеть VK/Iridium.

## Сверка дизайна

Источники: [мониторинг](https://www.figma.com/design/GxGegMJVi9NCC8FMG7Tgeb/?node-id=525-14756),
[Admin UI kit](https://www.figma.com/design/GxGegMJVi9NCC8FMG7Tgeb/?node-id=525-18242),
пользовательские скриншоты и ранее выгруженные ресурсы мини-приложения.

После замечания пользователя заново проверены композиция и основные размеры:
sidebar 240 px, header 72 px, реестр 1112 px с внутренней таблицей около 1064 px,
правая панель 480 px при ширине 1920. Восстановлены светлый фон, логотип,
иконки, нижнее подчёркивание активной вкладки, компактные поля/кнопки, строки
просрочки/SOS, быстрый ввод и отдельная карточка устройства. Лишние сводные карточки
убраны: в эталонном frame они скрыты. Тёмная тема выбирается явно.

Отличия по содержанию определяются API: официальная колонка не получает расчётное
GPS-время, нет фиктивных вложений/черновиков/графика батареи. Выбор КП оставляет
видимыми участников без отметки, чтобы судья мог её внести. Дополнительные
поддержанные операции доступны через «Инструменты этапа».

Детальные Figma-контексты и экспорт ограничены лимитом аккаунта. По согласованному
исключению использованы браузер, доступные метаданные, UI kit и присланные изображения;
точное попиксельное совпадение не заявляется.

## Что зависит от сервера и внешних интеграций

- Редактирование программы, локаций, FAQ, контактов и медиа — административного API нет.
- Вложения, черновики и отдельное поле источника подтверждения отметки — API нет.
- История батареи — API нет; отображается только последнее реальное значение.
- Фото участника — `photo_url`, отдельной загрузки файла нет.
- Реальная доставка VK push, разрешения/шеринг в зарегистрированном VK Mini App и
  поступление SOS из Iridium требуют действующих интеграций. Они **не считаются
  проверенными** по локальным тестам и Storybook.
- Фактическое наполнение программы, маршрутов, медиа и гостевых текстов остаётся
  у организаторов; отсутствующие материалы не придумывались.

Журнал реализации: [completion-log.md](completion-log.md). Предыдущий PR #4 не сливался;
его проверенные исправления включены в эту ветку вместе с новым backend.
