# Iridium360: разбор API и как мы его используем

Документация платформы: https://api.iridium360.ru/ (одна страница).
Код: `backend/app/services/iridium360/` — клиент (`client.py`), цикл опроса (`ingest.py`),
фоновый запуск (`poller.py`).

## Что даёт API

Один нужный нам метод — `/devices` (GET или POST), параметр `token` — токен пользователя
из личного кабинета организации.

- Без параметров: все устройства организации — `Name`, `Number`, `Imei` и
  `LastKnownPosition` (`Id`, `Date` UTC, `Lat`, `Lon`, `Cog` курс, `Sog` скорость, `Alt` высота,
  `Battery`).
- С `number` + `include_track=true`: трек **одного** устройства (`Track.Points`).
  Ограничить трек можно `date_from` / `date_to` или `point_id_from`.

Второй раздел документации (`/rockstar/send-message`) — отправка сообщений на трекер,
нам не нужен.

## Как опрашиваем

1. Раз в `TRACKER_POLL_INTERVAL_SECONDS` (120 сек) — `/devices`, один запрос на все трекеры.
2. Если последняя точка устройства новее нашей последней сохранённой — догружаем трек
   с `point_id_from` (пропуски, пока Iridium или наш сервер были недоступны).
3. Точку привязываем к участнику по `TrackerAssignment` на момент времени точки, этап — из
   привязки или по времени старта/финиша этапа.
4. Дубли отбрасывает база (устройство + id точки; устройство + время).
5. Неизвестный IMEI создаётся выключенным трекером — организатор привяжет его в админке.
   Точки трекеров без привязки не сохраняем.
6. Вне сезона (нет действующих привязок) Iridium не опрашиваем.
7. Сетевые ошибки — 2 повтора, потом пропуск цикла. Сервер продолжает работать на
   сохранённых точках.

Разбор ответа «терпеливый»: регистр ключей не важен, дата принимается в ISO, `ДД.ММ.ГГГГ`,
`/Date(мс)/` (ASP.NET) и числом. Точки без времени/координат и точки 0,0 отбрасываются.

## Ручная проверка

```bash
python backend/scripts/poll_iridium.py --check   # ключ и список устройств, в базу не пишет
python backend/scripts/poll_iridium.py --once    # один цикл с сохранением
```

## Открытые вопросы

| Вопрос | Статус |
|---|---|
| Ключ: `/devices` отвечает `500 Unknown error`, на выдуманный ключ — так же. Ключ не распознаётся | запрос куратору отправлен |
| SOS: в API нет данных о тревожной кнопке. Как получать? | вопрос в поддержку Iridium360 |
| Формат `Date`, единицы `Sog` и `Alt`, лимиты на частоту запросов | проверим на живом ответе |
| Временами нет соединения с api.iridium360.ru (порт 443) | наблюдаем; код делает повторы |
