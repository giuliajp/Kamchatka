# План работ бэкенда

Составлен по плану разработки от заказчика (три этапа) и брифу.
Работают два бэкендера: **опытный** и **новичок**.

Статусы: ✅ готово · 🔶 частично · ⬜ не начато · ⏸ ждёт данных от заказчика

Правило очерёдности: опытный сначала делает образец, новичок делает свои задачи по нему.

## Этап 3. Интеграция трекинга, история точек, ручные отметки КП; административная панель; push-логика

| № | Задача | Кто | Статус | Зависит от |
|---|---|---|---|---|
| 3.1 | API позиций для карты: последняя точка, «Положение на 14:32», флаг «неактуально», средняя скорость, расчётное положение | Опытный | ⬜ | 2.7 |
| 3.2 | История точек: трек участника, режим повтора | Опытный | ⬜ | 2.7 |
| 3.3 | Вход в админку для организаторов | Опытный | ⬜ | 2.1 |
| 3.4 | Ручные отметки КП (судейские) | Опытный | ⬜ | 3.3 |
| 3.5 | Админка: участники, заявки, этапы, КП, привязка трекеров (IMEI → участник → этап) | Опытный | ⬜ | 3.3 |
| 3.6 | Админка: мониторинг трекеров, сигнал SOS (только здесь, не в публичном API) | Опытный | ⬜ | 2.7, 3.3 |
| 3.7 | Админка: FAQ, программа, локации, переключение статуса гонки | Новичок | ⬜ | 3.3, 2.9, 2.10 |
| 3.8 | Проверка подписи параметров запуска VK | Опытный | ⬜ | 2.1 |
| 3.9 | Push-логика: события (старт этапа, смена лидера, КП, финиш), рассылки по сегментам, формулировки с учётом задержки | Опытный | ⏸ приложение в VK | 3.8, 3.1 |

> Ручные отметки КП (3.4) — официальный источник времени для результатов (2.6).
> Если результаты нужно показать раньше этапа 3, задачу 3.4 переносим в этап 2.
