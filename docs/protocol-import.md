# JSON → БД

Импорт принимает полный итоговый JSON гонки от
[PDF-парсера](protocol-parser.md).

## Запуск

Нужны PostgreSQL, настройки `backend/.env` и применённые миграции
([подготовка](../backend/README.md)). Переменные окружения имеют приоритет
над `.env`. Сервер API запускать не нужно.

Из корня проекта в активированном окружении:

```bash
python backend/scripts/import_protocol.py --json .cache/protocols/avacha-2026.json
```

`--json` — обязательный путь к файлу, `--help` — справка.
Команда выводит id гонки, число созданных записей и пропущенных результатов.
Коды завершения: `0` — успех, `1` — ошибка файла, данных, настроек или БД,
`2` — неверные аргументы. Ошибки и предупреждения выводятся в `stderr`.

## Правила импорта

- Гонка ищется по году, этап — по номеру внутри гонки, дисциплина — по коду.
  Спортсмен — по ФИО и году рождения: пробелы и регистр нормализуются,
  `е`/`ё` и дефисы сохраняются. Неоднозначное совпадение — ошибка.
- Для каждой пары «этап — дисциплина» создаётся протокол. Явные результаты
  DNF/DNS/DSQ сохраняются, пустые после DNF/DNS пропускаются.
- Время сохраняется из источника. Штрафы относятся к `RaceParticipant`
  за гонку и повторно к времени не прибавляются.
- Итоговое место переносится только в последний этап финишировавшего участника.
- Новая гонка и этапы получают `finished`, гонка — `is_current=False`.
  Протоколы создаются неопубликованными, со статусом `preliminary`.
- Общие статусы `finished`, `dnf`, `dsq` переносятся в участие напрямую.
  Для общего DNS участие получает `dnf`, если был завершённый этап или DNF,
  иначе — `registered`. Статус самого этапа остаётся `dns`.
- Совпадающие записи используются повторно. Отличающиеся значения и лишние
  этапы, участия, протоколы, результаты или штрафы в этой гонке — конфликт.
  Если есть опубликованный или утверждённый протокол, допускается только
  совпадающий повтор без создания записей.
- Предупреждения результатов и штрафов нужно устранить до импорта;
  отсутствие погоды и подписей судей допускается.
- Импорт выполняется одной транзакцией: при ошибке изменения откатываются.
  Данные других гонок и поля вне источника сохраняются.

Для вызова из Python используйте
`app.services.protocol_import.import_protocol(session, document)`
внутри `async with session.begin()`; сервис не выполняет `commit`.

Для исходного PDF ожидаются 21 участие, 18 протоколов, 118 результатов,
3 штрафа и 8 пропусков. При совпадающем повторе создано `0` записей.

В API результатов список участников должен строиться по `RaceParticipant`
с присоединением `StageResult`; при отсутствии результата показывается «—».

## Публикация

Импорт создаёт протоколы черновиками: API приложения их не показывает.
Пока в админке нет кнопки «Опубликовать» (задача 3.3), публикуйте командой:

```bash
python backend/scripts/publish_protocols.py --year 2026
```

Повторный запуск ничего не меняет. Проверка: http://127.0.0.1:8000/api/races/current
